Abstract

Sequence compression is a critical information bottleneck in efficient language and multimodal models. We revisit it through the lens of test-time regression: input tokens define a regression problem whose fitted coefficients form the compressed representation. The regression objective is learned end-to-end, while its coefficients are computed efficiently in closed form during the forward pass.

The resulting TTR-Compressor fits tokens jointly through their second-order correlations. It improves retrieval in block-wise sparse attention and consistently outperforms the standard MLP visual merger, matching its performance with 55.6% fewer visual tokens.

02 / Why it works

Learn what matters.
Adapt to what repeats.

A task-supervised objective.
An input-dependent representation.

TTR-Compressor combines two complementary mechanisms: training learns which regression problem produces useful summaries, and the inner solve adapts each summary to the relationships among the current tokens. This connects the compression rule to both the downstream task and the structure of each input.

01 / Task-supervised learning

The task shapes the regression.

Gradients from the downstream task pass through the exact solve to learn the target projection aaa and diagonal regularizer DDD. The objective is trained to produce useful representations, rather than merely to minimize the inner regression error.

The learned regularizer also shapes the similarity metric KD−1K⊤KD^{-1}K^{\top}KD−1K⊤, determining which feature directions matter when comparing tokens. At inference, these learned parameters remain fixed.

02 / Second-order adaptation

Redundancy has diminishing influence.

The Gram matrix couples all tokens in a group. Their effective weights are solved jointly, so repeated evidence has diminishing rather than purely additive influence. Distinctive information can retain a larger relative contribution when supported by the regression targets.

In the figure’s example, three identical tokens and one orthogonal token have equal targets and D=ID=ID=I. Pooling gives the two groups a 3 : 1 influence ratio; joint regression gives 3 : 2, increasing the distinct token’s relative share.

Why normalize only the keys?

Normalized keys make token similarity depend on direction, while targets retain the original feature magnitudes. If both used normalized features, the fixed projection aaa would exactly fit the regression targets, weakening the need for input-dependent adaptation. This asymmetry helps the fitted representation respond to each sequence.
